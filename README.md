# bip39-pm

Детерминированный менеджер паролей: все пароли вычисляются из одной seed-фразы BIP39
и имени сайта. Сервер не нужен, хранилища паролей нет. После потери устройства
пароли восстанавливаются из seed-фразы, никакой таблицы «сервис → пароль» не требуется.

> Статус: MVP — командная строка и мобильное приложение ManagerBIP ([mobile/](mobile/README.md)). Аудита кода не было — не используйте
> как единственное место хранения важных паролей.

## Как это работает

```
seed BIP39 (+ passphrase) → BIP32 → BIP85 m/83696968'/20567'/0' → k_app
k_app + домен + логин + счётчик + политика → HKDF-SHA256 → пароль
```

- Пароль — функция от `(seed, домен, логин, счётчик, политика)`. Тот же вход даёт тот же
  пароль на любом устройстве.
- `https://www.GitHub.com/login` и `github.com` — один и тот же сайт: домен нормализуется
  до eTLD+1 по Public Suffix List.
- Смена пароля = счётчик + 1.
- Необязательный зашифрованный индекс хранит счётчики и нестандартные политики.
  Его ключ тоже выводится из seed, паролей в нём нет.

Полный алгоритм и тестовые векторы — в [SPEC.md](SPEC.md).

## Установка

```sh
cargo install --path .
```

## Использование

```sh
pm new-seed                         # новая фраза из 24 слов
pm fingerprint                      # отпечаток seed: сверка после восстановления
pm get github.com vlad@mail.ru      # пароль для сайта
pm get bank.ru vlad --length 16 --no-symbols --save   # нестандартная политика → в индекс
pm rotate github.com vlad@mail.ru   # сменить пароль (счётчик + 1)
pm list                             # аккаунты из индекса
```

Seed-фраза и passphrase вводятся скрыто. Для скриптов можно задать `PM_MNEMONIC` и
`PM_PASSPHRASE`, но переменные окружения видны другим процессам — не делайте так на
рабочем компьютере. Индекс по умолчанию лежит в `~/.config/bip39-pm/index.pmx`
(путь меняется через `--index` или `PM_INDEX`); его можно синхронизировать через любое облако.

При каждом запуске печатается отпечаток seed из трёх слов. Запомните его: если после
восстановления слова другие — в фразе или passphrase ошибка.

## Безопасность

- Используйте для паролей **отдельную** seed-фразу или отдельную passphrase, а не ту,
  на которой лежат криптоактивы.
- Утечка seed раскрывает все пароли, и отозвать её нельзя: только сменить seed и все пароли.
- Утечка одного пароля не раскрывает ни seed, ни другие пароли.
