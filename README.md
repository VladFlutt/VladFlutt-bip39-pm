# bip39-pm

Детерминированный менеджер паролей: все пароли вычисляются из одной seed-фразы BIP39
и имени сайта. Сервер не нужен, хранилища паролей нет. После потери устройства
пароли восстанавливаются из seed-фразы, никакой таблицы «сервис → пароль» не требуется.

> Статус: MVP — командная строка, мобильное приложение ManagerBIP ([mobile/](mobile/README.md)), расширение для Chromium-браузеров и веб-приложение. Аудита кода не было — не используйте
> как единственное место хранения важных паролей.

## Как это работает

```
seed BIP39 (+ passphrase) → BIP32 → BIP85 m/83696968'/20567'/0' → k_app
k_app + домен + логин + счётчик + политика → HKDF-SHA256 → пароль
```

- Пароль — функция от `(seed, домен, логин, счётчик, политика)`. Тот же вход даёт тот же
  пароль на любом устройстве.
- `https://www.GitHub.com/login` и `github.com` — один и тот же сайт: домен нормализуется
  до eTLD+1 по Public Suffix List.
- Смена пароля = счётчик + 1.
- Необязательный зашифрованный индекс хранит счётчики и нестандартные политики.
  Его ключ тоже выводится из seed, паролей в нём нет.

Полный алгоритм и тестовые векторы — в [SPEC.md](SPEC.md).

## Установка

```sh
cargo install --path .
```

## Использование

```sh
pm new-seed                         # новая фраза из 24 слов
pm fingerprint                      # отпечаток seed: сверка после восстановления
pm get github.com vlad@mail.ru      # пароль для сайта
pm get bank.ru vlad --length 16 --no-symbols --save   # нестандартная политика → в индекс
pm rotate github.com vlad@mail.ru   # сменить пароль (счётчик + 1)
pm secret pin "карта сбер" --size 6  # PIN, кодовые слова (words), пароль Wi‑Fi (wifi), ключ SSH (ssh)
pm export > backup.txt              # код переноса PMX1:… для другого устройства
pm import < backup.txt              # влить код в свой индекс
pm list                             # аккаунты из индекса
```

Seed-фраза и passphrase вводятся скрыто. Для скриптов можно задать `PM_MNEMONIC` и
`PM_PASSPHRASE`, но переменные окружения видны другим процессам — не делайте так на
рабочем компьютере. Индекс по умолчанию лежит в `~/.config/bip39-pm/index.pmx`
(путь меняется через `--index` или `PM_INDEX`); его можно синхронизировать через любое облако.

При каждом запуске печатается отпечаток seed из трёх слов. Запомните его: если после
восстановления слова другие — в фразе или passphrase ошибка.

## Расширение для браузера

Расширение для Chrome, Edge, Brave, Яндекс Браузера и других браузеров на Chromium.
Оно использует то же ядро, собранное в WebAssembly, поэтому пароли совпадают с `pm`.

Сборка и установка:

```sh
sh extension/build.sh            # собирает extension/pm_core.wasm
```

Затем `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» →
папка `extension/`. Готовую сборку также можно скачать из артефактов CI
(`bip39-pm-extension`).

Как работает:

- Откройте страницу входа, нажмите на иконку расширения, введите seed-фразу
  (один раз за сессию) и логин. Кнопка «Заполнить» вставит пароль в форму.
- Домен берётся из адреса вкладки, а не со страницы. На фишинговом `g1thub.com`
  расширение выдаст другой пароль, и настоящий не утечёт.
- Seed-фраза не сохраняется. В памяти браузера (`storage.session`) хранится только
  производный ключ `k_app`; он стирается через 15 минут бездействия, по кнопке
  «Заблокировать» и при закрытии браузера.
- Индекс хранится зашифрованным в `storage.local`. «Экспорт» и «Импорт» используют
  тот же файл `.pmx`, что и `pm`.
- Доступ к странице расширение получает только в момент нажатия на иконку
  (`activeTab`), постоянных прав на сайты у него нет.

## Веб-приложение ManagerBIP

https://bip39-pm.vercel.app — статическая страница на том же WASM-ядре: работает в любом браузере, включая телефон.
Удобно, когда под рукой нет CLI и расширения.

```sh
sh web/build.sh                  # собирает web/dist
npx serve web/dist               # или любой статический сервер
```

- Seed-фраза, ключ и пароли не покидают вкладку. Политика безопасности (`vercel.json`)
  запрещает странице любые запросы, кроме загрузки собственных файлов.
- Ключ хранится только в памяти вкладки: перезагрузка, 5 минут бездействия или
  «Заблокировать» стирают его. В `localStorage` лежит лишь зашифрованный индекс.
- При первом запуске можно выбрать «Обучение» (демо-фраза, подсказки по шагам, ничего не
  сохраняется) или «Начать работу» (пошаговая настройка: новая фраза с проверкой записи
  или своя фраза, затем вход по паролю).
- Вход по логину и мастер-паролю (по желанию): при открытии seed-фразой можно создать вход,
  и дальше на этом устройстве seed вводить не нужно. Сохраняется не фраза, а `k_app`,
  зашифрованный ключом из Argon2id (64 МиБ, 3 прохода) — см. SPEC, раздел 8a. Мастер-пароль
  не короче 10 символов. Кто получит `localStorage`, сможет перебирать мастер-пароль офлайн,
  поэтому он должен быть длинным; забытый пароль не восстановить, только войти seed-фразой.
- Важно: веб-приложению вы доверяете каждый раз заново — тот, кто управляет хостингом,
  может подменить код. Для постоянной работы надёжнее CLI или расширение; веб-версия —
  запасной вариант.

Деплой на Vercel настроен в `vercel.json` и `web/vercel-build.sh`: Vercel собирает WASM и
публикует `web/dist`.

## Безопасность

- Используйте для паролей **отдельную** seed-фразу или отдельную passphrase, а не ту,
  на которой лежат криптоактивы.
- Утечка seed раскрывает все пароли, и отозвать её нельзя: только сменить seed и все пароли.
- Утечка одного пароля не раскрывает ни seed, ни другие пароли.

## Ключи Pro (`pm-license`)

Офлайн-ключи Pro подписываются Ed25519. Приватный ключ есть только у издателя, приложение
проверяет ключ вшитым публичным ключом без сети (`bip39_pm::License::verify`).

```sh
pm-license keygen --out issuer.key                       # один раз; печатает публичный ключ
pm-license issue --key issuer.key --from 1 --count 500 > batch1.csv   # пачка для маркетплейса
pm-license verify --pubkey <hex> MBIP-AEAQ-...           # проверить ключ покупателя
```

`issuer.key` храните офлайн и с резервной копией: без него новые ключи не выпустить,
а при утечке их сможет выпускать кто угодно. Серийные номера не должны повторяться
между пачками. Утёкшие ключи отзываются списком серийных номеров в обновлении приложения.
Публичный ключ издателя вшит в `mobile/rust/src/api/license.rs` (`PUBLISHER_KEY`),
там же список отозванных номеров `REVOKED`. Схема монетизации — в [docs/monetization.md](docs/monetization.md).
